## 🔧 Technical Details

### executeModelAction Flow
```
1. User calls executeModelAction({id: "input_34", action: "check"})
2. resolveSelector(id) → CSS selector
3. page.evaluate() loads models code
4. ModelRegistry.findModel() → CheckboxModel
5. CheckboxModel.getActionHandler("check") → "executeCheckAction"
6. executeCheckAction(page, element, "check", options)
7. Return result to user
```

### Model Detection Priority
```
Higher priority models checked first:
1. DatePickerModel (priority: 100)
2. MuiDatePickerModel (priority: 100) - future
3. AntDatePickerModel (priority: 100) - future
4. ...
5. DefaultModel (priority: -1000) - fallback
```

### isVisible() Fix
**Before**:
```javascript
if (style.opacity === '0') {
  return false; // ❌ Too strict - filters checkboxes
}
```

**After**:
```javascript
const isStylableInput = tag === 'input' && ['checkbox', 'radio', 'file'].includes(el.type);
if (style.opacity === '0' && !isStylableInput) {
  return false; // ✅ Allows stylable inputs with opacity:0
}
```

### 1. executeCheckAction Timeout

### 2. Checkboxes Not in APOM Tree
**Symptom**: Checkboxes with opacity:0 filtered out by isVisible()
**Root Cause**: Strict opacity check without exceptions
**Fix**: Allow checkbox/radio/file inputs with opacity:0
**Status**: ✅ Fixed

### 3. Browser Context Caching
**Symptom**: Code changes not applied after server restart
**Root Cause**: buildAPOMTree loaded once via eval(), cached in browser
**Solution**: Reload page after server restart to clear context
**Status**: ✅ Documented

## 🎓 Lessons Learned

### Architecture Decisions
1. **Separate models for each UI framework** - Approved
   - DatePickers too different to unify (input vs popup vs custom)
   - Clean architecture, easier to maintain
   - Framework-specific actions possible

2. **Strategy Pattern for model selection** - Working well
   - Priority system allows framework-specific override
   - Easy to extend without modifying core

3. **Reusable action handlers** - Good balance
   - Common actions (click, type) reused across models
   - Framework-specific actions (SetDate) separate

### Technical Insights
1. **Browser context caching**: Always reload page after code changes
2. **opacity:0 elements**: Need exceptions for stylable inputs
3. **MCP server restart**: Required for all code changes
4. **scrollIntoView importance**: Critical for reliable clicks
